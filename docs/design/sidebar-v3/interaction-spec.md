# Folio 侧边栏重设计评审稿

本稿的行为要求已获用户授权实现。最新主图与修订以 approved.md 为准。此前设计阶段的待审、只产图与不实施限制已被后续实现授权替代。

后续修订优先于本稿的旧视觉描述。主界面与图标方案见 approved.md 和 icon-spec.md。复制和重试现为纯图标，所有图标提供悬浮文字。

## 一、界面分成主对话与辅助页面

主对话只保留三块。顶部固定工具栏，中间独立滚动的对话，底部固定输入框。输入框包括文本区域、模式按钮、发送按钮。

顶部只有 Folio、新对话、课件、设置。新对话的加号不直接清空内容。已有内容时，先显示紧凑的确认提示，用户确认后才清空；取消保留原状。没有内容时无需确认。

课件与设置使用完整侧边栏子页面，顶部用返回箭头说明去向。它们不再从对话顶部展开，也不挤压对话。测试预览也使用子页面。返回时恢复原对话的草稿、选择的模式和阅读位置。

辅助页面的输入操作不隐式提交。设置只有“保存并返回”会保存。预览只有“写入文件”会写入项目。课件导入只有完成文件选择并确认导入后才修改资料库。

## 二、模式菜单有单一的开关状态

只保留“关闭”和“打开”两种状态。展开时只存在一个菜单实例。

| 当前状态 | 用户操作 | 结果 |
| --- | --- | --- |
| 关闭 | 点击模式按钮 | 打开菜单，标出当前模式 |
| 打开 | 再点同一个模式按钮 | 关闭菜单，保持关闭 |
| 打开 | 点击当前模式 | 关闭菜单，保留文本、模式与焦点位置 |
| 打开 | 点击其他模式 | 切换输入用途并关闭菜单 |
| 打开 | 点击菜单外或按 Esc | 关闭菜单，不切换模式 |
| 打开 | 上下方向键 | 移动菜单选项 |
| 打开 | Enter | 选择当前选项并关闭菜单 |

同一次指针手势只能造成一次状态变化。外部点击先关闭菜单时，同一个模式按钮的后续点击事件不能重新打开它。这里需要明确事件归属，不能靠延时或防抖遮盖。

菜单只列出“问答、练习、生成测试、提交信息”。课件从顶部文件夹直接进入，不属于模式菜单。

菜单浮在输入框上方，不改变对话高度。再次打开时，当前位置与选中项保持一致。

当前代码每次执行模式按钮的动作都会新建并显示 JPopupMenu。实机连续两次点击后菜单仍展开，与用户报告一致。自动关闭与再次显示的具体事件先后尚未记录为完整事件轨迹，因此不把这一推断写成已验证的事件级根因。

## 三、切换模式只影响下一次操作

历史消息不因切换模式而改写或更换。问答和练习不再共用一段没有归属的草稿。每个模式分别保留草稿、附带的代码上下文和输入位置。第一次进入新模式显示对应提示；再次返回恢复该模式上次未发送的内容。

| 模式 | 输入与上下文 | 结果 |
| --- | --- | --- |
| 问答 | 问题、可选的选中代码、已索引课件 | 回答与课件引用 |
| 练习 | 粘贴或选中的代码、可选要求 | 三道练习题与可展开解析 |
| 生成测试 | 明确展示源文件与代码上下文、测试要求 | 先生成测试预览，再由用户写入 |
| 提交信息 | 明确展示当前仓库与暂存改动范围、可选意图 | 候选信息，可复制或填入原提交框 |

发送时固定本次任务的模式与上下文。任务开始后切换模式，不改变正在执行的任务。没有源码或没有暂存改动时，在输入框附近说明缺少什么，并给出具体操作入口。不能只留下一个不可点击的按钮。

代码附件仅使用用户明确选择、粘贴或通过 IDE 操作带入的内容。切换文件不偷偷替换已附带的源码。

## 四、输入、发送和停止是一个连续过程

Enter 发送，Shift+Enter 换行。中文输入法候选确认不触发发送。两种快捷键在输入框提示中说明。

输入框保持底部对齐。内容增多时只向上增长，最多六行，超过后在输入框内滚动。清空后恢复最小高度，不移动发送按钮的水平位置。

一次发送只创建一次任务。快速双击不能重复发送。成功提交本次输入后清空该模式的输入区，并保留输入焦点。点击失败或校验未通过时不清空草稿。

生成时，同一位置的发送按钮变为停止按钮，输入框仍可编辑下一条草稿。不会在输入过程中把光标抢回回答。当前不增加自动排队功能。

停止只取消当前生成，保留已经收到的文字和下一条草稿。状态明确显示“已停止”。停止动作不清空历史。

按钮从停止变回发送时，当前指针手势必须先结束，新角色才接受后续操作，避免一次点击取消后又把下一条草稿发出去。

失败信息放在当前回答末尾，并提供“重试”。如果已经输入下一条内容，恢复失败问题不能覆盖新草稿。重试使用原问题与对应上下文，不额外插入一条重复的用户消息。

## 五、阅读位置由用户控制

用户在底部阅读时，新增内容跟随到最新位置。用户向上滚动、拖动滚动条或选择文字后，停止自动跟随。通过“回到最新”恢复跟随；这个按钮只在离开底部且存在新内容时出现，不占用固定底栏。

打开模式菜单不滚动对话。打开设置与课件后返回，不滚动到末尾。展开来源时保留当前回答在屏幕中的位置。

流式正文沿用同一份内容，不在每次更新时替换整个可选中文本组件。完成时不突然重建整条回答。正在选择文字时，不因为最终格式化而丢失选区。

## 六、回答、引用与局部反馈

普通回答直接排版在对话中，不套整块大卡片。回答底部固定一组复制与重试图标按钮，不显示常驻文字，不在顶部重复放复制按钮。

复制成功时，原图标短暂变为对勾，悬浮提示变为“已复制”。失败时在同一按钮的提示中说明原因。按钮占位保持一致，不让正文随反馈移动。键盘聚焦也能到达操作并读取说明。

引用默认收成“2 处课件引用”。展开后按文件名、页码或章节、简短摘录排列。点击文件名打开原文件或现有来源预览；摘录仍可选择复制，不能整行任何位置都跳转。收起来源不改变回答内容。

没有检索到课件依据时，在当前回答附近明确说明依据边界。不能把普通模型回答伪装成课件引用。此项保留现有证据校验能力。

## 七、课件页面

文件夹图标直接打开课件列表。文件行展示文件名、页数或幻灯片数、索引状态。空列表在同一区域显示导入提示。

点击导入进入系统文件选择器。取消不改变已有资料库。导入期间在该任务附近显示进度。成功后更新文件行，失败时保留可用旧资料并就地说明原因。

同一文件的再次导入明确执行更新；替换整个资料库必须是显式动作，不能把“导入”实现成静默删除原有文件。课件仍在项目间共享，并在列表上方说明。

文件行的省略号只放文件相关操作，例如重新索引、移除。移除前明确提示是否影响共享资料库。

## 八、设置页面

字段纵向排列，依次是 API 地址、模型、API Key。字段错误紧贴对应字段。未连接提示放在主输入框附近，并提供“去设置”。

API 地址必须是真实提供商地址。图片里的地址仅为布局示例，不表示校园网访问或连接已经验证。

已保存的 Key 只显示保存状态或遮罩占位，不能从钥匙串取出后自动填进明文字段。眼睛按钮仅切换本次手动输入的显示方式。Key 留空时保留原凭证。

“移除已保存的 Key”先标记本次修改意图，保存时才执行，避免取消表单后凭证已经丢失。“取消”和返回放弃未保存表单，保留原配置。

“保存并返回”进行本地校验与保存，成功后恢复原对话。失败留在设置页，保存按钮附近显示原因。保存成功不等于已验证外部服务可用，文案不能误报连接成功。

## 九、练习、测试和提交信息

练习直接作为回答展示三道题。每题解析独立展开与收起，展开不影响其他题目。原问题及上下文仍在同一会话中。

测试先显示明确的目标文件与完整预览。写入前重新检查目标路径、文件是否变化、是否可写。失败保留预览并说明原因。已有文件不能静默覆盖。成功后提供打开目标文件的入口。

提交信息在会话中按候选排列，每个候选旁边直接提供“复制”和“填入提交框”。生成完成不自动改剪贴板，也不自动填入提交框。操作前保留对暂存内容和原提交框是否变化的检查。不会执行 git commit。

这些变化重组现有能力，不以简化界面为由删掉课件检索、来源预览、生成测试、受保护写入或提交信息能力。

## 十、动效规则

反馈先发生，动画不能延迟命令执行。悬停、按下和焦点只改变当前控件的背景或轮廓。输入框不缩放，按钮不弹跳。

菜单使用很短的淡入淡出，不伸缩正文。页面切换不滑动整块长内容。默认不对阅读位置执行补间动画。展开解析和引用时只过渡局部内容，并保持阅读锚点。

过渡可中断。用户反向操作时立即接受新意图，不排队播放旧动画。遵循系统减少动态效果设置。具体时间需在实现后实测，不把毫秒数当作手感验收结果。

## 十一、按图实现的约束

三张图片共九个状态。每个侧边栏按约 360×760 的逻辑尺寸审阅，图外编号、白底或拼图背景不是产品界面。图片中的示例正文、文件名和代码是示例数据；按钮、字段、菜单项目、提示文案和位置属于设计内容。

主布局以 01-chat.png 为准，辅助页面以 02-pages.png 为准，其他任务与未连接状态以 03-workflows.png 为准。保留紧凑字级、小图标、底部输入框和克制的层次。

图片尚有需要在用户审阅后统一的细节，例如不同图中的图标笔画和蓝色按钮材质。它们不是授权实现时自由改动的范围。用户选定版本后，先统一评审图，再冻结图片、文案与尺寸表。

没有画出的重要布局状态，包括引用展开、文件操作菜单、错误与新对话确认，需要补图后再实现。简单局部文字反馈只替换现有占位，不增加新布局。

实现必须用真实 IntelliJ 截图与冻结图片逐项对照。对齐、间距、文字、图标大小、按钮位置和九个状态都要检查。发现实现约束与图片冲突时，先提出差异并修改评审稿，不自行换布局或省略能力。

## 十二、必须实机验收的操作

1. 模式按钮点击一次打开，再点击一次关闭，停留后仍关闭。
2. 菜单打开后点当前项、其他项、外部、Esc，各自只产生一次预期结果。
3. 连续切换模式后，草稿、上下文与历史消息保持正确。
4. 输入中文候选、换行、粘贴长代码、发送，不误发、不跳焦点。
5. 生成时编辑下一条，停止当前任务，下一条草稿不丢失也不误发。
6. 阅读上方内容时持续接收回答，阅读位置和文字选区保持稳定。
7. 打开设置与课件再返回，恢复原输入与阅读位置。
8. 保存设置、复制、导入失败时，反馈出现在操作附近。
9. 预览测试不写文件，确认写入时保留原有路径与变更检查。
10. 提交候选不会自动覆盖剪贴板或已改变的提交框。

静态评审图不能证明上述交互通过。只有真实界面操作与结果检查才能完成验收。
